# QuorumMind Optimization Checklist

创建时间：2026-06-18

## 当前判断

QuorumMind 的 Decision Room 和 Blueprint Room 已经具备可用闭环：中文体验、真实模型调用、兜底、共识收敛、终局评估、质询采纳账本、实施任务清单、导出报告、视觉审计和质量审计都已覆盖。

后续优化重点不应该继续堆说明文字，而应该提升“可交付、可审计、可回归、可维护”。

## 优化清单

- [x] 1. Blueprint 实施任务清单可单独导出
  - 目标：用户能把生成的 issue 级任务清单单独导出为 Markdown，直接交给团队或放进项目管理工具。
  - 验收：页面有“导出任务清单”按钮；导出文件包含优先级、负责人、阶段、依赖、交付物、验收标准和跳过风险；测试覆盖。

- [x] 2. Blueprint 任务清单支持复制为纯文本
  - 目标：无需下载文件，也能一键复制任务清单到飞书、Notion、GitHub Issue 或 Jira。
  - 验收：页面有复制任务清单入口；复制内容和导出 Markdown 一致；有成功提示。

- [x] 3. Blueprint 面板支持折叠长内容
  - 目标：共识、评估、建议、采纳账本、任务清单内容越来越长后，中间栏仍然易读。
  - 验收：长面板默认展示摘要，可展开查看完整内容；移动端不拥挤；视觉审计通过。

- [ ] 4. Blueprint 结果摘要增加“下一步 3 件事”
  - 目标：非技术用户不需要读完整蓝图，也能知道现在最应该先做什么。
  - 验收：最终结果顶部显示 3 个最高优先级任务或建议，和任务清单数据一致。

- [ ] 5. 真实模型贡献采纳状态细化
  - 目标：不仅展示真实模型贡献，还要标记每条贡献是采纳、部分采纳、拒绝还是待验证。
  - 验收：报告和页面能解释每条模型贡献的处理原因。

- [ ] 6. 真实 API Blueprint 回归测试
  - 目标：用固定 20-30 个 Blueprint 问题跑真实模型，记录中文、相关性、schema、兜底和可用性。
  - 验收：生成独立真实模型质量报告，包含失败样本和改进建议。

- [ ] 7. 导出包合并
  - 目标：一次导出包含蓝图 Markdown、任务清单、报告 HTML、Prompt 包和原始 JSON trace。
  - 验收：新增“导出完整包”入口，至少用 JSON/Markdown 组合文件实现。

- [ ] 8. 前端 bundle 体积优化
  - 目标：当前构建出现 chunk size warning，后续应拆分导出/报告/历史等非首屏代码。
  - 验收：构建不再出现 500kB chunk 提醒，视觉和功能测试通过。

- [ ] 9. Blueprint 历史记录
  - 目标：当前历史偏 Decision Room，Blueprint 结果也应可保存和恢复。
  - 验收：运行过的 Blueprint 能在历史里打开，保留问题、来源、模型轨迹和结果。

- [ ] 10. 设置页
  - 目标：如果未来给别人用，需要把 API key 状态、CORS、Token、模型连接测试、导出设置集中展示。
  - 验收：用户无需看 README 或控制台，也能判断配置是否正确。
