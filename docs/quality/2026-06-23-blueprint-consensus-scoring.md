# 2026-06-23 蓝图共识分动态化修正

## 背景

方案蓝图多次出现最终共识分 `93%`。排查后确认不是前端写死，但旧算法存在固定档位：

- deep 模式轮次增量固定为 `[0, 11, 19, 23]`。
- 视觉小说/多 Agent 场景常见基础分为 `87`。
- 真实模型贡献按数量最多加 `6` 分，容易得到 `87 + 6 = 93`。

这会让用户误以为共识分是写死的，也会削弱指标可信度。

## 修正

已将蓝图共识分改为动态信号计算，主要信号包括：

- 草案覆盖度：工作流阶段、Schema 字段、风险、待确认问题、thesis 具体度。
- 质询覆盖度：质询数量、评审角色覆盖、差异化建议数量、质询具体度。
- 修订吸收度：采纳建议数量、修订覆盖、修订说明质量。
- 结构覆盖度：工作流、Schema、上下文约束、Agent 覆盖。
- 问题具体度：问题长度、编号需求、领域词、上下文完整度。
- 分歧压力：独立 critical gap、开放问题、差异化建议和 red-team 压力。

真实模型贡献加分也从固定数量加分改为质量加权：

- recommendation 是否充分。
- usefulIdeas / cautions 是否丰富。
- 来源是否多样。
- 标题、来源和建议内容是否可用。
- 采用递减收益：基础共识分已经较高时，真实模型只能小幅确认，不能把分数机械抬到固定高档位。

随后继续补充了题材区分信号：

- CRM / 销售线索
- 订单 / 库存 / 广告 / 客服对话
- 合同 / 制度 / 文档审查
- 会议 / 任务 / 风险 / 周报
- 培训 / 课程 / 内容
- Agent / Schema / 复审
- 指标 / 评估 / 延迟 / 成本 / 采纳

这样短参考问题不会全部落到同一个分数；高可用 live trace 也不会把多个问题机械推到 `93%`。

- 弱模型贡献和强模型贡献带来的共识提升不同。

## 当前解释口径

蓝图共识分不是静态写死，也不是完全等同于真实模型“投票一致率”。它现在是 QuorumMind 对蓝图过程质量的综合评分：

`草案覆盖 + 质询充分度 + 修订吸收 + 结构完整度 + 问题具体度 - 分歧压力 + 可用真实模型贡献`

如果未来要进一步接近真实语义共识，可以继续加入 embedding 相似度、LLM judge 分歧归因和跨 provider 观点聚类。
